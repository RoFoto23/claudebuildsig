# DECISIONS.md

Each entry: decision, reason, what it costs us.

1. **One product, BuildSignal for trades; QuoteCheck (homeowner side) not built.** Two products doubles support, legal and SEO load for a solo owner. QuoteCheck also needs an LLM and a ROC lookup that has no verified source. Cost: no homeowner revenue stream.
2. **Zero-dependency Node 22, plain ES modules, server-rendered HTML, no JavaScript in the browser.** The build environment could not reach npm or pip, and fewer dependencies means fewer supply-chain and upgrade chores for a non-developer owner. A strict Content-Security-Policy (`script-src 'none'`) is possible because no page needs script. Cost: no HTMX niceties; every button is a plain form post; hand-written PostgREST and Stripe clients instead of SDKs. This deviates from the recommended Python/FastAPI stack; reason above.
3. **Vercel functions + Supabase Postgres + Resend + Stripe (hosted Checkout and Portal).** Lowest owner-time stack with automatic TLS, backups on the paid tier, and no server to patch. Cost: Vercel Hobby is non-commercial, so Pro is required; Supabase free tier pauses and has no backups, so Pro is required before real customers.
4. **Only two cron jobs** (`ingest` 04:00 AZ, `digest` 06:00 AZ). Hobby-compatible and enough. Housekeeping rides on ingest; reminders ride on digest. The digest job continues itself (`?depth=N`) if it runs out of its 40-second budget.
5. **Arizona has no daylight saving**, so cron UTC times are fixed: ingest `0 11 * * *`, digest `0 13 * * *`.
6. **Passwordless login.** Single-use sha256-hashed tokens, 20-minute expiry. GET shows a confirm button and only POST consumes the token, so email scanners cannot burn links. Sessions are HMAC-signed cookies with a revocable epoch.
7. **Admin = allowlisted email + role + TOTP (RFC 6238) with replay protection**, secret encrypted with AES-256-GCM. Every admin action is written to `audit_log`.
8. **Tap links (Interested / Not for me / Already knew) are signed, expiring and require a deliberate click.** A plain GET from a mail scanner shows a confirm page instead of changing data.
9. **Rules first. Originally no LLM; a model is now an optional fallback ONLY for forwarded emails (decisions 21-28), off by default.** For public-record matching nothing uses a model. Matching is deterministic and every checklist line is explained. Nothing requires inventing a date, requirement or licence rule, so the "extract once, match many" LLM path, the 60-solicitation evaluation set and prompt-injection tests from the brief are not applicable to public-record matching. For the forwarded-email fallback the injection corpus and guards ARE built (`test/eval.test.js`, `docs/EVAL-RESULTS.md`); the 90% extraction target is **unmeasured** until real alert emails exist.
10. **Scores use five transparent weights** (fit 30, timing 25, scale 15, access 15, evidence 15) editable in Admin > Rules. Customer feedback nudges per-customer weights by at most +/-10. Unknown values (missing ZIP, missing value) show **yellow "unknown"**, never silently pass or silently fail. (Regression tests cover the prototype's multi-ZIP, missing-ZIP, zero-value and unmatchable-trade bugs.)
11. **Live sources ship disabled and terms-gated.** Unknown terms = blocked. The public demo never touches live sources.
12. **Public demo uses 10 real permit records (Mesa and Scottsdale) from a research snapshot, frozen**, evaluated against a fixed "now". Labelled "Sample snapshot" everywhere; buttons on the demo are labelled simulated. Cost: the demo ages; it is a demo of the format, not the live feed.
13. **Signup opens only when database, email, billing, mailing address and secrets are all configured.** Until then the landing page says "Early access" and collects a waitlist. No fake "alerts delivered" screens: with no email key, messages are stored as `simulated` and the UI says so.
14. **Prices:** Starter $29 and Pro $49 per month, 14-day trial, card required at checkout. Database CHECK enforces price <= $50 and the admin form rejects more. No annual plan (would exceed the cap). Editable in Admin > Pricing; changing a price archives the old Stripe price and creates a new one on next checkout.
15. **Capability statement is a print-ready page**, saved as PDF from the browser's print dialog. WeasyPrint was not available. The UI says "Save as PDF" and does not claim a generated PDF file.
16. **Mail pacing 120 ms between sends** (Resend default limit is 10 requests/second per team), retry on 429/5xx, idempotency key per message.
17. **Inactivity rule:** 14 unopened digests in 30 days pauses that customer's digests automatically (protects sender reputation). "No strong matches" notes are throttled to once per 7 days for daily customers.
18. **Out of scope (not built):** Spanish, SMS, referral rewards, annual plans, ROC verification feed, past-performance builder, additional portals. (The admin review queue and inbound forwarding ARE now built, see 21-28; both ship off.) Listed so the site never claims them.
19. **Mobile check:** verified at 500 px width in headless Chromium (its minimum window width); layout has no horizontal overflow. A real-device check is still the owner's job.
20. **Known limitation:** changing a disposition does not reverse the earlier feedback weight nudge. Impact is small (capped at +/-10).

## Forwarded-alert inbox (decisions 21-30)
21. **Feature:** a contractor forwards bid-alert emails (BidNet, state portal, PlanHub, BuildingConnected, anything) to a private tokenized address; we read them, drop duplicates, score them with the same rules as everything else and include the good ones in the 5-item digest. **Ships OFF** (`inbox.enabled` = false). It must not be switched on for customers until (a) the live webhook check (T13) passes and (b) real forwarded emails have been run through the parser. Neither has happened.
22. **Reuse `/webhooks/resend`** (event `email.received`, same Svix signing secret) instead of a second endpoint. The webhook carries metadata only; the body is fetched from Resend's API under an 8-second budget, and a sweeper finishes anything left over.
23. **Privacy by structure:** forwarded items are `opportunities` rows with `owner_account_id` set. Shared items load once for everyone; owned items load per account and are scored only for their owner. Admin's opportunity list excludes them. Tests: `test/isolation.test.js`, `test/e2e-inbox.test.js`.
24. **Parsing tiers:** sender templates (empty on purpose: no real alert email has been seen, so none were invented) -> generic rules -> model fallback only if the rules found nothing or no deadline. Every field needs a verbatim quote from the email; dates, amounts and links are re-derived from the quote; a link must be http(s) and literally present. Model-reported confidence is ignored; we recompute it.
25. **Model is off unless ALL of:** `llm.enabled`, API key, model name, a monthly dollar cap, and input/output prices per million tokens (owner-entered from the provider's price page; the app does not guess prices). Spend is logged per call in `llm_calls` (tokens, cost, latency, outcome; no email text). At the cap the model is not called and the email waits in the review queue. Provider request shapes (Gemini default, Claude, OpenAI) are written from documentation memory and are **unverified** until T13.
26. **Mixed results:** if an email yields at least one good item, weaker items from the same email are dropped; zero good items -> the message is held for review (never invented, never silently discarded).
27. **Schema deviations from the design doc:** a `held_items jsonb` column was added (prefills the review form); `inbox_addresses.local_part` is stored in plaintext rather than hashed because the page must show the address back to its owner (it is a revocable capability token, rate-limited per day).
28. **Review queue = 9th admin screen** (`/admin/review`). Staff can release (typing only what the email states; blank stays blank; deadline entered in Arizona time and validated as a real calendar date), drop, or retry. Released items are labelled to the customer as staff-entered. Staff can read held email text: this is disclosed on the customer inbox page and must be in the Privacy policy.
29. **Open bids now rank ahead of permit leads in every digest** (`selectForDigest`). The brief requires private-sector GC leads to rank below open bids; the old pure-score sort let 72-84 point permit leads push a 62 point open bid out of the top 5. Found by the 500-customer load test. Within each tier, higher score first.
30. **Spend history survives account deletion** (`llm_calls.account_id` set to null); email content does not (cascade delete, plus content blanked after 30 days).
